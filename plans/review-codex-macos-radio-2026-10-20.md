   **Should-fix — separate retirement accounting and logging.** `RETIREMENTS` and `CAP_SAID` are process-global. After a radio object has heard a reply, three interactions that successfully write but hear nothing retire it—even when the keyboard merely went to sleep. Repeated answer/silence cycles can consume all six retirements, preventing a genuinely deaf USB object from recovering until capacity returns. `CAP_SAID` can also suppress the other object’s diagnostic. 3. **The flock ownership model is appropriate; creation and permissions need tightening.**

   **Note — correct lifetime and exclusion.** On macOS, exclusive flock works on a read-only descriptor and conflicts across processes **and across independent opens in one process**. It belongs to the open-file description, unlike a POSIX process-owned record lock. `RadioLock(File)` therefore releases on drop; forgetting the boxed guard keeps its descriptor and lock alive until process exit. The shared code requires only this lifetime contract: it retains the guard across ticks, drops it on release, and forgets it after `Stuck`. No byte-range or Windows-specific locking behavior is required. See [radio_lock.rs:18](/Users/jdlien/code/ak820-pro/ak820-agent/src/platform/macos/radio_lock.rs:18), [radio_lock.rs:36](/Users/jdlien/code/ak820-pro/ak820-agent/src/platform/macos/radio_lock.rs:36), [platform/mod.rs:31](/Users/jdlien/code/ak820-pro/ak820-agent/src/platform/mod.rs:31), [radio.rs:165](/Users/jdlien/code/ak820-pro/ak820-agent/src/radio.rs:165), and [radio.rs:341](/Users/jdlien/code/ak820-pro/ak820-agent/src/radio.rs:341).

   **Should-fix — creation race and cross-user availability.** Two users can both observe `NotFound`; one creates a `0644` file, then the other’s read-plus-append open fails despite having sufficient read permission to lock it. Ordinary concurrent creation does **not** produce two lock files, but this race unnecessarily disables radio for 60 seconds. Use exclusive creation and retry an existing file read-only. Also, `0666` is umask-filtered, and directory creation does not ensure cross-user traversal: umask `077` can leave `0700`/`0600`, permanently excluding another user. Establish explicit directory/file permissions if cross-user operation is promised. These failures are closed, not concurrent ownership. See [radio_lock.rs:29](/Users/jdlien/code/ak820-pro/ak820-agent/src/platform/macos/radio_lock.rs:29) and [radio.rs:242](/Users/jdlien/code/ak820-pro/ak820-agent/src/radio.rs:242).

Match Windows: skip `Ok(None)`, fail `Err`. See [macOS radio_lock.rs:62](/Users/jdlien/code/ak820-pro/ak820-agent/src/platform/macos/radio_lock.rs:62) versus [Windows radio_lock.rs:95](/Users/jdlien/code/ak820-pro/ak820-agent/src/platform/windows/radio_lock.rs:95).

   **Note — script integration.** At this commit, the script still uses `lockf` and opens for append; the Rust comment already describes the planned flock conversion. Include read-only opening of existing files in that conversion. Also preserve the lock file’s inode: flock does not provide Windows’ prohibition on deleting or replacing a held file.
