The remaining and newly introduced issues, ranked:

1. **Must-fix — the restored drain still violates ACK-before-pump.** Two 34-byte requests followed by an ACK put that ACK beyond the 64-byte cap. Pumping there can retransmit an already-acknowledged A-frame; its duplicate ACK can subsequently release the next frame. Calling this pre-existing does not close finding 1. Specify bounded catch-up and safe behavior on **every** incomplete-drain exit, including a split ACK. The drain is byte-bounded, **not demonstrably time-bounded**: it still executes battery handlers and synchronous ACK writes. [Code](C:/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/keyboards/a_jazz/ak820pro/bluetooth/ch582f_ajazz.c:1721).

2. **Must-fix — complete the two-report receipt contract.** UART submission order does not establish lossless, ordered delivery through the closed module and dongle; the existing experiment sends only one reply per transaction. Require paired-frame delivery/pacing tests and a host state machine: exact lengths/shapes, status validation, matching identity and reply CRC, bounded candidate lifetime, and clearing on mismatch, timeout or reconnect. **Either half missing means incomplete/unknown execution, never success**; receipt-first must fail safely. Also protect the receipt’s `seq/status/last` with integrity checking—the reply CRC does not cover them. Otherwise corruption can change the very identity being trusted. [Plan](C:/Users/jdlien/code/ak820-pro/plans/RAWHID-24G-PLAN.md:398), [existing permissive NAK classification](C:/Users/jdlien/code/ak820-pro/scripts/raw81_proto.py:44).

3. **Must-fix — freshness needs a session and reuse policy.** Immediate duplicates are rejected, and `255 → 0` works. But old `seq=0` becomes “fresh” at `last=129`, since the difference is 127. Reset/link change accepts any first old request; host restart can reuse an outstanding identity; after 256 requests an old reply/receipt pair can match again. “Never reuses a seq” is impossible with eight bits. Define session establishment across board reset, link change and host restart, plus sufficiently wide identities or a justified packet-lifetime/non-reuse bound. Enforce one owner per dongle; one outstanding request **per process** is insufficient. Advance freshness only for admitted requests, not drops or rejected commands. [Plan](C:/Users/jdlien/code/ak820-pro/plans/RAWHID-24G-PLAN.md:413), [host truncates sequence to eight bits](C:/Users/jdlien/code/ak820-pro/scripts/raw81_proto.py:39).

4. **Must-fix — the ACK-window removal needs an explicit experimental gate.** The evidence establishes **zero ACKs observed inside those windows**, not that `91` never produces a late/conditional ACK. An orphan counter is blind when an A-frame is in flight: that ACK instead pops the A-frame. Retain a guarded configuration while validating longer `91`-only, paired-`91`, and mixed-key runs; require host-observed key preservation before enabling removal. [Plan](C:/Users/jdlien/code/ak820-pro/plans/RAWHID-24G-PLAN.md:436), [430-observation endpoint](C:/Users/jdlien/code/ak820-pro/history/raw81-echo-20261019-gremlin/tick-20-gap100.json), [ACK consumer](C:/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/keyboards/a_jazz/ak820pro/bluetooth/ch582f_ajazz.c:1057).

5. **Should-fix — define the response slot as one transaction containing both frames.** Keep reply and receipt metadata immutable and reserved until both are submitted or the transaction is cancelled. Do not copy the current “clear pending before first write” lifecycle. Two frames occupy 68 UART bytes; a 128-byte output queue does not guarantee 68 bytes are free or make `sdWrite()` nonblocking. Measure the resulting key delay. [Plan](C:/Users/jdlien/code/ak820-pro/plans/RAWHID-24G-PLAN.md:406), [current lifecycle](C:/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/keyboards/a_jazz/ak820pro/bluetooth/ch582f_ajazz.c:967).

6. **Should-fix — make acceptance observable and consistent.** A text echo is another write, not stored-state readback; current health reads do not expose text. Specify a read-only diagnostic for text/playback state. Slot-full tests must expect counted drops/timeouts, not a NAK. Add lost/reordered receipt halves, delayed packets across wrap/restart, cap-hit ACK ordering and nested-drain tests; measure transaction latency through receipt completion. [Matrix](C:/Users/jdlien/code/ak820-pro/plans/RAWHID-24G-PLAN.md:451), [text storage](C:/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/keyboards/a_jazz/ak820pro/graphics/display.c:2183).
