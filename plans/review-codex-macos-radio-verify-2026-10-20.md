3. **Note — ordinary creation races and another user’s `0644` file work.**

   Exclusive creation makes the loser retry read-only against the existing inode. An existing foreign-owned `0644` file takes the initial `File::open` path: no write permission or file chmod is required. A second user’s failed directory chmod is harmless when the directory already permits traversal and the file is readable. Successful chmod changes permissions, not the inode. See [radio_lock.rs:27](/Users/jdlien/code/ak820-pro/ak820-agent/src/platform/macos/radio_lock.rs:27) and [radio_lock.rs:49](/Users/jdlien/code/ak820-pro/ak820-agent/src/platform/macos/radio_lock.rs:49).

   **Should-fix — cross-user permission recovery remains incomplete.** An existing `0600` file is returned immediately when its owner opens it, so even that owner’s new daemon never repairs its permissions. Another user remains excluded. With fresh creation under umask `077`, another user can also open between creation and chmod, receive `PermissionDenied`, and incur the 60-second lock-error backoff. Ignored chmod failures can leave restrictive permissions indefinitely. These are availability failures; they do not grant concurrent ownership. Repair owner-controlled existing permissions and verify the intended access guarantees. Evidence: [radio_lock.rs:35](/Users/jdlien/code/ak820-pro/ak820-agent/src/platform/macos/radio_lock.rs:35), [radio_lock.rs:51](/Users/jdlien/code/ak820-pro/ak820-agent/src/platform/macos/radio_lock.rs:51), and [radio.rs:242](/Users/jdlien/code/ak820-pro/ak820-agent/src/radio.rs:242).

   **Should-fix — qualify the inode-protection claim.** Sticky mode blocks unrelated users from replacing another user’s file, but the **file owner, directory owner, and root** can still replace it. Ignoring chmod failure also means sticky mode is not guaranteed. Thus the inode concern is only partly answered. The current Rust and Python participants preserve the inode; continued correctness requires preserving that convention while any holder remains alive. Correct the “only the file’s owner” wording at [radio_lock.rs:31](/Users/jdlien/code/ak820-pro/ak820-agent/src/platform/macos/radio_lock.rs:31) and [plan:442](/Users/jdlien/code/ak820-pro/plans/RAWHID-24G-DAEMON-PLAN.md:442).
