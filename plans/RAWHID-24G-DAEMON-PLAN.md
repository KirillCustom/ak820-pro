# Now-playing over the 2.4G dongle: the daemon's second transport

Status: **draft for codex's review (10-19), nothing built.** Owner: the
Gremlin session (Windows); the macOS half is the Mac session's. Depends on
raw HID over 2.4G stage 2 (`plans/RAWHID-24G-PLAN.md`), on the board since
`b4b6662f` (`ak820pro-jdlien`), dev builds only.

## What it is for

With the cable in, `ak820-agent` sends now-playing text and the playback
readout over USB raw HID, and owns the clock. Unplugged, in 2.4G, the board
shows nothing from the host. Stage 2 gives an allow-listed raw-HID path over
the dongle with a reply and a CRC-checked receipt per request, ~25 ms a
transaction, measured on gremlin (999-998/1000, the losses the board's own
counted overrun taints). This plan puts **now-playing and playback** on that
path when the cable is absent. **The clock stays on USB only** (stage 3 of
the raw-HID plan), and so do health reads.

## The shape (from the map of `ak820-agent/`)

- The text path is `agent::cycle` (agent.rs:365): one `P::open_board()` per
  media tick, then `send` (`request_echoed`, Channel::Text) for the SET_LINE
  pair or CLEAR, then the PLAYBACK report every tick. `Publisher` (media.rs)
  decides when text is due (on change, or a 30 s keepalive).
- `Platform::open_board()` is shared by media, clock and health, with one
  presence `Watch`. **The radio must not be added there**: a second opener
  (`open_radio()`), used only by the media cycle, so the clock and health can
  never reach it by construction.

## Design

**D1. A raw81 protocol module in Rust (`src/raw81/`).** The host side of
stage 2, ported from `scripts/raw81_proto.py`: `crc16` (CCITT-FALSE, table),
`envelope(session, seq, inner)` (26-byte inner, refusing longer), the receipt
parser (its own CRC), `reply_shaped`, and the `Transaction` state machine of
R4-3 exactly. Tests: every case of `raw81_proto.py`'s self-test, plus golden
vectors generated by the Python (envelopes and receipts for fixed inputs), so
the Rust and the Python, and through `raw81_test.py` the board's C, agree.

**D2. The radio device.** Windows: the dongle's `MI_03` (`0C45:FDFD`, usage
page FF60, usage 61, 33-byte reports) found through the Configuration
Manager's list with `path.rs`'s strict hardware-id filter (VID/PID as
arguments, `mi_03`), opened shared like the board, its identity checked with
the dongle's own usage pair; a second dongle is `Ambiguous`. It implements
`Wire` (33-byte write and read with the existing overlapped I/O). macOS: the
Mac session's (IOKit, the FF60/61 collection of `0C45:FDFD`). A `Platform`
method `open_radio()` returns it; `Platform::open_board()` is untouched.

**D3. The radio transaction.** `RadioLink::request(inner) -> Result<Reply>`:
drain the handle (every input report goes to every open handle on Windows),
allocate the next seq, write the envelope, feed every report to the
`Transaction` until it closes or the 100 ms deadline passes (checked before
feeding). Results map to the agent's errors: `ok` -> the reply (checked
against the command as `request_echoed` checks a USB echo); `nak` 1 (bad
CRC) or `unknown` -> one retry on a new seq, then a failed push; `nak` 2 (not
allowed) -> a hard refusal (a board whose allow-list lacks text: disable the
radio until its build changes); `nak` 3 (stale) -> resynchronise the seq from
the receipt's last admitted seq, retry once; `nak` 4 (busy) -> another owner:
back off 30 s; `incomplete` -> a failed push (retried next tick).

**D4. Session and ownership.** One owner per dongle per machine: the daemon
takes the same lock file the test scripts use
(`%LOCALAPPDATA%\ak820pro\raw81-session.json.lock`, held for the radio's
lifetime, not just a transaction) and its own single-instance mutex already
excludes a second daemon. The session id is persisted in
`raw81-session.json` before the first send, incremented on every open, and
the open waits until 1 s after the previous open (R5-2); state that exists
but cannot be read fails the radio closed (never reallocates from 1). The seq
span is rotated before 16,384 issued (an idle second, then a new session).

**D5. When to use the radio.** Per media tick:
1. Try USB exactly as today. If the board is present, the radio is not used.
2. Only if USB says `Absent` (not Busy, Refused or Abandoned, which mean the
   board is there): if the radio is **enabled** and **qualified** (D6) and the
   dongle is present, send the same reports over the radio.
The radio has its own presence `Watch` and its own backoff (60 s after a
`Stuck`, as USB), so a sleeping board or an absent dongle costs nothing but a
CM list call a tick, and logs only on a change.

**D6. Qualification: never send to a board that cannot take it.** A daily
build has no collector: a `81` frame's bytes go to its 3-byte window, where a
payload could form a valid `5B` or `5C` (the Mac session's hazard). So the
radio is used only for a board **seen over USB to run a stage-2 build**: on
every USB presence (the daemon already reads health), it reads `HC_DEVHOOK`
op 17 (a read; unhandled on daily and pre-stage-2 builds) and the build
token (`HC_GET6`, health page 6, already decoded in `health.rs`), and stores
`(token, stage2: bool)` in the status directory. The radio is qualified only
while the stored record says stage 2 for the last token seen. A reflash needs
the cable, and the daemon sees the new token on that USB presence before any
radio use, so the record cannot go stale unnoticed; with no record (never
seen over USB) the radio stays off. Separately (raw-HID plan): put the
collector in every build, so a `81` is always consumed whole even where
dispatch is dev-only, removing the hazard at the source.

**D7. Opt-in.** A daemon flag `--radio` (both platforms' parsers, an install
flag persisted in the Scheduled Task / LaunchAgent arguments like `--clock`),
off by default. `ak820 status` prints the radio's state, qualification and
last result; the status file gains `radio_*` fields.

**D8. Publication over the radio.** The same `Publisher` and reports: the
SET_LINE pair (or CLEAR) on change and every 30 s, PLAYBACK every tick
(3 s). At ~25 ms a transaction that is ~3 transactions a tick at most. A
failed text push leaves `Publisher` where it was, so the next tick retries, as
on USB.

## Tests

- `raw81` unit tests: the Python self-test's cases, golden vectors from the
  Python, every `Transaction` ordering.
- A fake radio `Wire` (the existing `Fake` scripted with receipts) driving
  `RadioLink`: ok, each NAK, incomplete, unknown, stale resynchronisation,
  busy backoff, a corrupt receipt, a foreign receipt.
- The cycle's transport choice through an opener seam (the map found no fake
  `Platform`): USB present -> USB only; USB absent and the radio unqualified
  -> nothing sent; qualified -> the radio.
- Qualification: the token record written on a USB presence, a changed token
  clearing it, a missing record keeping the radio off.
- On the board (gremlin, then the Mac): the cable out, a track playing, the
  band shows title and artist within a tick and the playback readout ticks;
  the board asleep -> no errors logged beyond one presence change; the cable
  back -> USB again, no radio traffic; `stream`-style counters on the board
  (drops, deferral overruns, short writes: 0).

## Not in this plan

The clock over the radio (stage 3). Health over the radio. A daily build's
dispatch. Bluetooth (no vendor channel; FEE0 is the module's OTA).

## Revision 2: after codex's plan review (10-19)

[Review](review-codex-rawhid-daemon-plan-2026-10-19.md), verbatim: not ready as
written; ready once its seven must-fixes are resolved. Revision 2 replaces
the sections above where they differ.

**R2-1. Qualify over the radio, with a probe old firmware cannot misread
(must-fixes 1, 2).** A record of a board once seen over USB cannot prove what
the dongle reaches now (codex: a reflash while the daemon is stopped, a second
board, a stale positive). So qualification moves onto the radio itself:
- An older build's 3-byte window can only match `5A|5B|5C <d> <sum>` or
  `61 0D 0A`. A 34-byte `81` frame containing **none of the bytes 0x5A, 0x5B,
  0x5C or 0x61** can match neither, in any alignment, so a pre-stage-2 board
  ignores it entirely: no LED state, no link state, no battery reading.
- The **probe** is such a frame: the health read `07 13 01`, an envelope whose
  session, seq and CRC bytes, and whose outer sum, avoid those four values (the
  host steps the seq until they do, at most a few tries in practice; the
  session id itself is chosen to avoid them).
- A stage-2 board answers the probe with a reply and a receipt: the board on
  the radio, now, is qualified. No answer within the deadline: not qualified
  (a daily or older build, a sleeping board, or nothing linked); the radio
  stays idle and re-probes on a backoff.
- Qualification lasts for the radio's current acquisition only. It is dropped
  on any probe or request timeout, any `Unknown`, a USB presence (the cable
  is in: USB takes over; a reflash needs the cable), a dongle arrival, and
  the daemon's start. So text, whose bytes include 'Z' (0x5A) and 'a' (0x61),
  is only ever sent to a board that answered a probe since the last time
  anything could have changed it.
- Unknown health tokens, HC_GET6, and op 17 are no longer part of the gate.

**R2-2. Ownership and the session (must-fix 3).** The daemon takes the same
kernel byte-range lock as `win_raw81_s2.py` (`msvcrt.locking` on the lock
file's byte 0 is `LockFileEx` on byte 0), **per user** (`%LOCALAPPDATA%`; the
board's `BUSY` keeps two users' daemons from interleaving), held for the
radio's acquisition, released when USB takes over or the radio idles out, and
taken without blocking (contention defers radio work to a later tick). The
older echo scripts do not take it; they are dev tools and documented as not
to be run beside the daemon. Session state is written durably and atomically
(temp file, flush, rename) before the first send; a missing file starts at
session 1 only if no lock holder exists; unreadable or rolled-back state
(a session lower than the one this process last used) fails the radio
closed. The 1 s reopen wait is measured on the monotonic clock, with the file
holding the wall time only as a cross-process floor (a wall-clock jump
backwards waits at most 1 s more).

**R2-3. Errors without sequence jumps (must-fix 4).** No resynchronisation
to `last_seq + 1`: a `STALE` (this session's identity is no longer fresh)
**rotates the session** (the idle second, then a new id), which keeps every
identity unique by construction. `BUSY` on the daemon's own fresh session
(its previous one admitted something under a second ago, e.g. a restart)
waits the idle once and retries; `BUSY` otherwise backs the radio off 30 s.
One retry per request in total, whatever the reason.

**R2-4. The exchange contract (must-fix 5).** The radio uses the transport's
own drain (`drain_until`, bounded, `Queue::Empty` required before a write) and
its error types; `Stuck` at any point (drain, write, read) ends the tick's
radio work at once and puts the radio in the 60 s abandoned backoff, as USB.
The 100 ms is the transaction's read deadline, checked before feeding; a
write's own timeout and a cancellation's grace come on top, so it is not a
wall-clock bound. `Incomplete` (the board dispatched; the reply was lost) and
`Unknown` (it may not have) stay distinct in logs and counters; neither
commits the publisher.

**R2-5. Outcomes separated, not just openers (must-fix 6).** The radio's
interface is **text-only** (`set_lines`, `clear`, `playback`), built on the
`raw81` module; no generic request. Its results go to a radio `Watch` of
its own; the USB `Watch`, backoff and status fields are never touched by
radio results. The fallback is chosen from the USB **opener's** `Absent`
only, not from any cycle failure (a macOS `Absent` mid-transfer is a USB
failure, retried on USB next tick).

**R2-6. Tests at the boundaries (must-fix 7).** The cycle gets two seams,
an opener (USB, radio) and an injected clock and session store, so it runs
on fakes without a fake `Platform`. Cases added: the probe's byte rule
(property: no window match in any alignment for every probe built), an old
board (no answer: never text), qualification dropped by each trigger, lock
contention and persistence failures (missing, unreadable, rolled back, a
temp file left behind), rotation on `STALE`, `BUSY` own and foreign, every
USB error state (only the opener's `Absent` selects the radio), clock and
health never reaching the radio (compile-time: the text-only interface),
dirty drains, late completion, and `Stuck` in each phase. Timing tests use the
injected clock (the existing `Fake` ignores timeouts).

**R2-7. A sleeping board and handover (should-fixes 8, 9).** Radio silence
(timeouts with the dongle present) backs off 1 s, 2 s, 4 s ... to 30 s and
logs once per transition; on macOS, radio silence is the radio's state, not a
deaf USB device. On any change of transport, or a new radio qualification,
the publisher's next push is a full text refresh (not after the 30 s
keepalive). The status file reports the active transport separately from
USB presence; qualification and session storage are kept apart from the
best-effort status telemetry. Install combinations of `--radio` and
`--clock` are tested.

**Note taken:** one Configuration Manager snapshot per tick, shared by the
USB and dongle openers.
